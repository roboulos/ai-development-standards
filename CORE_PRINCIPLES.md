# 🎯 Core Development Principles
*Universal standards for all AI-assisted development*

## 🦉 Ray's Strategic Principles

### ⚡ Value Creation Over Implementation
- Focus on 10x value work, not just coding
- Build capabilities, not just features
- Create leverage through reusable patterns
- Delegate low-value implementation work

### 🏝️ "Closer Island" Development
- Short, sharp engagements (1-2 weeks max)
- Clear beginning, middle, and end
- Defined deliverables with specific endpoints
- No open-ended commitments

### 💰 Revenue-First Mindset
- Prioritize features that enable immediate revenue
- Simple solutions before complex ones
- WhatsApp/API before fancy portals
- Test with real money ASAP

## 🏗️ Technical Standards

### API Design Principles
1. **Resource-based naming**: `resource/action` format
2. **Consistent responses**: Same structure everywhere
3. **Multi-tenant by default**: Security from day one
4. **Activity logging**: Audit trail on everything
5. **Pagination standard**: page/per_page parameters

### Security Requirements
1. **Authentication required**: No public endpoints
2. **Multi-tenant isolation**: Users see only their data
3. **Role-based access**: Granular permissions
4. **Input validation**: Never trust client data
5. **Error masking**: Don't leak system details

### Code Quality Standards
1. **Pattern reuse**: Don't reinvent the wheel
2. **Clear naming**: Self-documenting code
3. **Error handling**: Graceful failures
4. **Performance conscious**: Consider scale
5. **Documentation inline**: Update as you code

## 🤝 AI Collaboration Principles

### Starting Sessions
1. **Read documentation first**: Full context before coding
2. **Verify environment**: Instance, workspace, auth
3. **Check current status**: Know exactly where we are
4. **Plan before building**: Think, then execute

### During Development
1. **Follow patterns exactly**: They're battle-tested
2. **Update documentation immediately**: Not at end
3. **Test one, build many**: Verify then scale
4. **Ask when uncertain**: Better safe than sorry

### Ending Sessions
1. **Update status docs**: Leave clear handoff
2. **Document new patterns**: Build knowledge base
3. **Note blockers**: Help next session
4. **Celebrate progress**: Acknowledge wins

## 🚀 Productivity Patterns

### The Assembly Line Method™
1. Build 2-3 examples manually
2. Verify pattern works perfectly
3. Use automation for bulk creation
4. Test comprehensively
5. Document immediately

### Rapid Development Flow
1. **Morning**: Read docs, plan approach
2. **Midday**: Build core functionality
3. **Afternoon**: Test and refine
4. **End**: Update documentation

### Knowledge Compound Effect
- Every pattern documented
- Every solution reusable
- Every session builds on last
- Exponential improvement over time

## 💡 Decision Framework

### When to Build
- Enables immediate revenue
- Creates reusable capability
- Solves validated problem
- Has clear success metrics

### When to Defer
- Nice-to-have features
- Complex UI requirements
- Speculative functionality
- Low-impact improvements

### When to Simplify
- Portal → WhatsApp
- Custom → Standard
- Complex → Simple
- Perfect → Good enough
